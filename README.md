# Pocket Jira для Telegram

Закрытый Telegram Mini App для ведения задач небольшой команды. Приложение работает как Kanban-доска, использует MongoDB Atlas как основное хранилище, развёртывается на Vercel и умеет выгружать текущий список задач в Google Sheets.

> Статус документа: описывает текущую реализацию репозитория. Обратный импорт из Google Sheets в MongoDB пока не реализован.

## Возможности

- Вход только из Telegram Mini App с проверкой подписи `initData`.
- Доступ для пользователей из белого списка `ALLOWED_USER_IDS`.
- Создание, перемещение и удаление задач.
- Пять статусов: **Беклог**, **В работе**, **Блок**, **Выполнено**, **Отменено**.
- Четыре приоритета: **Низкий**, **Средний**, **Высокий**, **Критический**.
- Защищённые DevTools для разработчика: справочник команды и одноразовые приглашения.
- Регистрация коллег через команду боту `/start` по одноразовой ссылке.
- Экспорт задач из MongoDB в первую вкладку Google Sheets, включая dropdown-списки.

## Архитектура

```mermaid
flowchart LR
  T[Telegram Mini App] -->|initData + JSON| A[/api/auth]
  A --> M[(MongoDB Atlas)]
  A -->|Экспорт| S[Google Sheets]
  B[Telegram Bot] -->|Webhook /start| W[/api/bot]
  W --> M
  D[DevTools в Mini App] -->|Управление справочником| A
```

MongoDB является источником истины для задач. Google Sheets сейчас используется только как экспортируемое представление задач.

## Технологии

- Статический HTML/CSS/JavaScript без фронтенд-фреймворка.
- Vercel Serverless Functions на Node.js.
- MongoDB Node.js Driver.
- Google Sheets API через пакет `googleapis`.
- Telegram Mini Apps SDK и Telegram Bot API.

## Локальный запуск

```bash
npm install
npx vercel dev
```

Для полноценной авторизации Mini App нужно открывать приложение из Telegram. В обычном браузере оно покажет экран с ошибкой Telegram-сессии.

## Переменные окружения

Все значения задаются в Vercel: **Settings → Environment Variables**. Не добавляйте секреты в Git и не присылайте их в чаты.

| Переменная | Обязательна | Назначение |
|---|---:|---|
| `MONGODB_URI` | Да | Строка подключения MongoDB Atlas. |
| `BOT_TOKEN` | Да | Токен Telegram-бота; используется для проверки `initData`. |
| `ALLOWED_USER_IDS` | Да | Telegram ID пользователей Mini App через запятую. |
| `DEV_USER_IDS` | Для DevTools | Telegram ID разработчиков через запятую. Это более узкий доступ, чем белый список. |
| `BOT_USERNAME` | Для приглашений | Username бота без `@`; нужен для формирования ссылки `t.me`. |
| `TELEGRAM_WEBHOOK_SECRET` | Для webhook | Случайная строка, которую Telegram передаёт в заголовке webhook. |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | Для экспорта | E-mail сервисного аккаунта Google Cloud. |
| `GOOGLE_PRIVATE_KEY` | Для экспорта | Закрытый ключ сервисного аккаунта. Допустимы многострочное значение и строка с `\n`. |
| `GOOGLE_SPREADSHEET_ID` | Для экспорта | ID Google-таблицы из её URL. |

Пример `ALLOWED_USER_IDS`:

```text
123456789,987654321
```

## Развёртывание и Telegram webhook

1. Создайте проект Vercel и добавьте переменные окружения.
2. Выполните deployment в окружение Production.
3. Укажите Telegram webhook на адрес:

   ```text
   https://<ваш-домен>/api/bot
   ```

4. При `setWebhook` передайте тот же `TELEGRAM_WEBHOOK_SECRET` как `secret_token`, ограничьте типы обновлений значением `message` и задайте небольшое `max_connections` (например, `5`).

Webhook принимает только `POST` с корректным заголовком `X-Telegram-Bot-Api-Secret-Token` и обрабатывает только личные сообщения.

## Авторизация Mini App

Каждый запрос Mini App к `/api/auth` содержит Telegram `initData`. Сервер:

1. Удаляет поле `hash` из параметров `initData`.
2. Собирает отсортированную строку параметров.
3. Проверяет HMAC-SHA-256 подпись с `BOT_TOKEN` по схеме Telegram Mini Apps.
4. Сверяет Telegram ID пользователя с `ALLOWED_USER_IDS`.
5. Определяет права разработчика по `DEV_USER_IDS`.

Клиент не передаёт доверенный идентификатор автора: сервер извлекает пользователя из подписанных Telegram-данных.

## API Mini App: `/api/auth`

Все JSON-запросы, кроме изменения статуса и удаления, используют `POST`. Во всех запросах нужен `initData` в теле либо заголовок `x-tg-init-data`.

### `POST` — вход и загрузка доски

```json
{
  "initData": "<telegram-init-data>",
  "action": "login"
}
```

Возвращает задачи, отображаемое имя пользователя, белый список и флаг `isDeveloper`.

### `POST` — создание задачи

```json
{
  "initData": "<telegram-init-data>",
  "action": "create",
  "task": {
    "text": "Проверить доступы",
    "executor": "Иван З",
    "deadline": "2026-08-15",
    "status": "todo",
    "priority": "high"
  }
}
```

Допустимые коды статусов: `todo`, `progress`, `blocked`, `done`, `cancelled`.

Допустимые коды приоритетов: `low`, `medium`, `high`, `critical`.

Автор определяется сервером. Если пользователь есть в `team_members` и ему задан `displayName`, он становится автором новой задачи; иначе используется имя Telegram.

### `PUT` — перемещение задачи

```json
{
  "initData": "<telegram-init-data>",
  "taskId": "1723710000000",
  "newStatus": "progress"
}
```

Используется при drag-and-drop карточки.

### `DELETE` — удаление задачи

```json
{
  "initData": "<telegram-init-data>",
  "taskId": "1723710000000"
}
```

Перед запросом интерфейс просит подтверждение. При успехе карточка удаляется из MongoDB и с доски.

### `POST` — экспорт в Google Sheets

```json
{
  "initData": "<telegram-init-data>",
  "action": "sync_google"
}
```

Экспорт всегда берёт данные из MongoDB и записывает их в **первую вкладку** указанной Google-таблицы. Это не импорт из Sheets.

### DevTools API

Эти действия доступны только пользователям из `DEV_USER_IDS`.

| `action` | Назначение |
|---|---|
| `list_team_members` | Возвращает справочник команды. |
| `create_invite` | Создаёт одноразовое приглашение, действующее 24 часа. |
| `update_team_member` | Обновляет `displayName` и `team` пользователя из справочника. |

Пример обновления пользователя:

```json
{
  "initData": "<telegram-init-data>",
  "action": "update_team_member",
  "member": {
    "telegramId": "123456789",
    "displayName": "Иван З",
    "team": "Разработка"
  }
}
```

## Telegram webhook: `/api/bot`

Webhook нужен для безопасного наполнения справочника данными Telegram.

### Поток приглашения

1. Разработчик открывает DevTools и нажимает «Создать приглашение».
2. Приложение формирует ссылку `https://t.me/<BOT_USERNAME>?start=join_<token>`.
3. Коллега открывает ссылку и нажимает Start.
4. `/api/bot` проверяет секретный заголовок, личный чат, формат команды и одноразовый токен.
5. В `team_members` записываются данные Telegram пользователя.
6. В DevTools разработчик задаёт понятные `displayName` и `team`.

Обычная команда `/start` без валидного приглашения не записывает пользователя в MongoDB.

## MongoDB

База данных: `pocket_jira`.

### Коллекция `tasks`

```json
{
  "id": "1723710000000",
  "status": "todo",
  "text": "Проверить доступы",
  "author": "Иван З",
  "executor": "—",
  "deadline": "2026-08-15",
  "priority": "medium",
  "createdAt": "2026-08-15T09:00:00.000Z"
}
```

Сейчас автор и исполнитель хранятся строками. Это совместимо с существующими задачами, но не решает однофамильцев окончательно. Планируемая модель — хранить `authorId` и `executorId` как Telegram ID, а имя получать из справочника.

### Коллекция `team_members`

```json
{
  "telegramId": "123456789",
  "telegramFirstName": "Иван",
  "telegramLastName": "Зайцев",
  "telegramUsername": "ivan_example",
  "displayName": "Иван З",
  "team": "Разработка",
  "registeredAt": "2026-08-15T09:00:00.000Z",
  "lastSeenAt": "2026-08-15T09:00:00.000Z",
  "updatedAt": "2026-08-15T09:00:00.000Z"
}
```

`telegramId` — постоянный технический ключ. `telegramUsername` полезен для отображения, но не должен быть ключом: он может отсутствовать или меняться.

### Коллекция `bot_invites`

```json
{
  "token": "join_<случайная-строка>",
  "createdAt": "2026-08-15T09:00:00.000Z",
  "expiresAt": "2026-08-16T09:00:00.000Z",
  "createdById": "123456789",
  "usedAt": "2026-08-15T10:00:00.000Z",
  "usedById": "987654321"
}
```

Webhook создаёт уникальные индексы по `team_members.telegramId` и `bot_invites.token`, а также TTL-индекс по `bot_invites.expiresAt` для автоматического удаления просроченных приглашений.

## Google Sheets

### Требования Google Cloud

1. В проекте Google Cloud включите Google Sheets API.
2. Создайте сервисный аккаунт и сохраните его e-mail и закрытый ключ в переменные Vercel.
3. Откройте нужную таблицу Google Sheets и дайте сервисному аккаунту роль **Редактор**.
4. Укажите ID таблицы в `GOOGLE_SPREADSHEET_ID`.

Для API используется scope:

```text
https://www.googleapis.com/auth/spreadsheets
```

### Формат первой вкладки

Строка 1 принадлежит пользователю. Код её не очищает и не переписывает. Один раз задайте в ней заголовки:

| Колонка | Заголовок | Тип |
|---|---|---|
| A | Текст задачи | Текст |
| B | Статус | Dropdown |
| C | Автор | Dropdown |
| D | Исполнитель | Dropdown |
| E | Due Date | Дата или пустая ячейка |
| F | Приоритет | Dropdown |

При каждом экспорте строки `A2:Z1000` очищаются и заново заполняются задачами из MongoDB. Валидация dropdown устанавливается для строк 2–1000:

- **Статус:** Беклог, В работе, Блок, Выполнено, Отменено.
- **Автор и исполнитель:** элементы справочника команды, а также временно значения старых задач.
- **Приоритет:** Низкий, Средний, Высокий, Критический.

Если срок отсутствует, в `Due Date` записывается пустая строка. При наличии срока приложение экспортирует его в виде `dd.mm.yyyy`.

### Ограничения текущего экспорта

- Используется только первая вкладка файла; вкладка выбирается по её порядку, а не имени.
- Любые вручную внесённые значения в строках 2–1000 будут удалены при следующем экспорте.
- Импорта изменений из Google Sheets в MongoDB нет.
- Технические скрытые колонки (`taskId`, `authorId`, `executorId`) и лист справочника ещё не созданы.
- Колонка `Notes` запланирована, но сейчас не выводится.

## Интерфейс Mini App

### Kanban-доска

Карточку можно перетащить в любую из пяти колонок. У каждой карточки есть кнопка `×`, которая удаляет задачу после подтверждения.

В мобильном Telegram начало drag-and-drop определяет WebView Telegram: отдельная задержка долгого нажатия в коде не задана.

### Форма создания

Форма содержит:

- текст задачи;
- исполнителя;
- статус;
- срок;
- приоритет.

Автор подставляется сервером из Telegram-сессии и не выбирается вручную.

### DevTools

Блок находится под доской, свёрнут по умолчанию и вообще не выводится пользователям без права разработчика. В нём можно:

- создать одноразовую ссылку-приглашение;
- посмотреть зарегистрированных участников;
- изменить `displayName` для интерфейса и экспорта;
- указать команду или роль.

## Безопасность и эксплуатационные замечания

- Не раскрывайте `BOT_TOKEN`, `MONGODB_URI`, приватный ключ Google и webhook-secret.
- Сервисный аккаунт Google должен иметь доступ только к нужной таблице.
- `DEV_USER_IDS` не должен включать всех пользователей приложения без необходимости.
- Доступ к задачам сейчас общий для всех пользователей из `ALLOWED_USER_IDS`: авторство не ограничивает редактирование и удаление.
- CORS у `/api/auth` сейчас разрешён для всех источников, но защищён Telegram `initData`.
- Проверка подписи `initData` есть, но срок `auth_date` пока не ограничивается. Его стоит добавить до расширения аудитории приложения.
- Идентификатор новой задачи сейчас основан на `Date.now()`. При росте нагрузки его следует заменить на UUID или MongoDB `ObjectId`.

## Проверки перед deployment

```bash
node --check api/auth.js
node --check api/bot.js
node --check script.js
git diff --check
```

После изменения `script.js` обновляйте параметр версии в конце `index.html`, например:

```html
<script src="./script.js?v=20260815-3"></script>
```

Это помогает Telegram WebView не использовать старую кэшированную версию скрипта.
